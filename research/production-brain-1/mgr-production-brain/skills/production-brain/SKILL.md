# MGR Production Brain 1

Own the production decisions before delegating synthesis to a model. Use the installed MGR BEAST Pack as the research operating contract when invoked. Do not replace its rules or claim that this plugin contains a complete film studio.

Start with [native-tools.md](references/native-tools.md) and [capabilities.json](assets/capabilities.json). Execute supported tools during the task; reading instructions or returning a catalog is not completion. The host agent interprets natural language; native modules perform deterministic work. Use Node 24.21 or a compatible newer runtime with node:sqlite. If the host exposes no filesystem/Node execution, these packaged modules are unavailable in that host; do not pretend they are connected MCP tools.

Read [all-75-branch-studies.md](references/all-75-branch-studies.md) for individual methods, alternatives, dependencies, failure fixtures and remaining evidence. Read [execution-and-comparison.md](references/execution-and-comparison.md) before durable job bookkeeping or the actual Blender fixture, and [hollywood-output-comparison.md](references/hollywood-output-comparison.md) before making production-quality or competitor claims. There are75 individual engineering studies; their presence does not mean all original child research is closed. Continue accessible research and implementation instead of treating populated fields as completion.

## Execute the workflow

1. Inspect the user's project and existing canonical requirements, context locks, assets and approved designs. Creation OS owns those records when present. Read only relevant records; do not substitute the example's characters for the user's canon.
   Before choosing implementation paths, read [research-use.md](references/research-use.md), search the embedded catalog with `node <skill-root>/scripts/research.mjs search <concrete terms>`, and inspect matching tracks. Expand dependencies with `plan <track IDs>`. Research is for this plugin first. Continue unresolved accessible research during the authorized build; a queue entry is not permission to stop. Reuse findings in Creation OS without claiming that its app has integrated a module merely because files are present.
2. Preserve the exact request in `rawRequest`. Interpret natural language using the host agent; the JavaScript compiler is deterministic and is not a language model. Record assumptions. Ask only about consequential unresolved creative choices or true blockers. Proceed with reversible drafts.
3. Read [production-method.md](references/production-method.md) for film/animation/VFX planning and [website-method.md](references/website-method.md) for websites. Decompose the deliverable into shots or routes, assets, dependencies, approval/verification criteria and reusable context. Film names are references for specific craft decisions, never proof of studio-level output.
4. Create a versioned plan using [example-plan.json](assets/example-plan.json) and [plan-contract.md](references/plan-contract.md). Replace every example detail. Include start/end states, temporal beats, motivated camera choices, light direction, sound, identity constraints and criteria for each shot. A short request should result in a useful draft, not an unnecessary questionnaire.
5. Run `node <skill-root>/scripts/brain.mjs validate <plan.json> [previous.json]`. Fix reported errors. Standalone projects then use `production.mjs save-plan <project.sqlite> <plan.json> <expected-revision>` so stored history supplies the predecessor. Admit local reference bytes with `admit-asset`; use the resulting digest and actual inspection scope. Never remove a lock to make a check pass. Local storage is not a multi-tenant authorization service.
6. Run `node <skill-root>/scripts/brain.mjs compile <plan.json> neutral` for a provider-independent handoff. Save stdout as a new artifact, never overwrite the approved plan. Inspect the actual result. `impact <previous.json> <next.json>` lists affected shots after a revision.
7. Read [provider-boundaries.md](references/provider-boundaries.md) before routing. Refresh actual model/tool schemas and pricing when execution is needed. Optional MCP connections require account authorization. Discover their tools; never invent names. `compile <plan.json> minimax-h3` checks a documented text-only draft. `minimax-h3-max` selects that explicit variant. Other providers receive the neutral handoff until their live schema has been inspected.
8. Before a paid request, retain the exact payload, selected model, quoted price, user budget and existing spending authorization. `budget <handoff.json> <quote.json> <budget.json>` checks digest/expiry/currency/arithmetic only. Passing does not authorize spending. If a provider rewrites prompts, compare the rewritten result against locks before generation; MiniMax H3 Context IR returns a prompt, not a video.
9. Execute through available authorized tools only after those checks. Preserve request IDs and original results. Do not retry an ambiguous paid submission without reconciliation. Download transient provider outputs to approved durable storage; retain provenance and inspect actual rendered media. Never mark a prompt, mock, or submitted job as a verified film.
10. Evaluate intent, identity, motion, camera, physics, edit, sound, function, performance and cost separately. Repair failed criteria and branch the affected work. Record researched/implemented/tested/verified states separately and add discovered gaps to the BEAST queue.

For camera work, author physical scene inputs and execute `camera-check`; repair collisions before provider handoff. For editorial work, choose an explicit frame rate and integer trims, execute `timeline`, save the `otio` object as an OTIO draft, and flag missing media. For supported content websites, translate the request into the site contract, execute `site-build`, inspect the generated file and verify it in a browser where available. Use a full application workflow for unsupported backend/multi-route requirements. Read the embedded native research packets before extending these modules.

## Truthful handoff

Implemented: plan/prompt checks; persistent standalone plans and asset versions; exact byte recovery; bounded PNG/PCM-WAVE structural inspection; static-proxy camera path and sampled framing checks; cuts/gaps editorial assembly with OTIO draft export; single-page motion content-site generation; individual research retrieval; durable local provider-job bookkeeping; matched-comparison completeness and artifact checks. An authored Blender CPU fixture executed actual bake/save/reopen/render; its procedural result and static USD camera round-trip were measured. This does not establish arbitrary rendering, complex fracture/dust/rigging/compositing, neural identity control, complete codec decoding, arbitrary web applications, live provider transport, a trustworthy price feed or signed spending authority. Never label unexecuted adapters or unreached quality targets as complete.

Never embed keys in plans, prompts, packages, reports or source control. Server login does not imply MCP authorization. Do not upload local assets merely to validate their plan. Read public sources and licensed implementations; do not bypass paid libraries or access private competitor systems.

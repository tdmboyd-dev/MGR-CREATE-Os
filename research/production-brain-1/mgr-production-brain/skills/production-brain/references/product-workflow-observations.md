# Product workflow research — 2026-10-01

These are selected public product observations. They are separate from live account schemas, source inspection and output trials. No competitor application, paid prompt library or private model was acquired.

## MiniMax Design

Source: https://design.minimax.io/ — intake, canvas, skill ecosystem, local asset center and review/delivery sections read. The advertised desktop workflow combines brief interpretation, connected media nodes, reusable skills, local assets and review checkpoints. Its marketing comparison and testimonials do not establish measured superiority. The linked tutorial redirected to a Feishu login and was not read; no desktop runtime or private plugin implementation was inspected.

MGR implementation decision: requirements and review state belong to the canonical revision; node inputs bind asset versions and provider schemas. Store outputs before presenting completion. Existing Brain 1 revision/asset tools cover bounded native contracts, while a full canvas scheduler, desktop bridge and rich editable timeline remain implementation work. An approval checkpoint is required where authority actually needs it, not for every routine reversible step.

## YouArt

Sources: https://www.youart.ai/tutorial/agent-and-workflow-guides and https://www.youart.ai/workflow — agent phases, selected-node refinement and workflow/editor sections read. The tutorial describes concept direction, character turnarounds, plot/video production and rough editing. Refinement retains the original node and creates an adjustment node. The public workflow page advertises canvas/timeline integration but does not expose its internal node schemas or scheduler.

MGR implementation decision: local edits become immutable revisions with explicit dependency invalidation. Preserve approved source results and regenerate only affected descendants. A host can interpret language, but structural validation does not prove semantic fidelity. Required evaluation must include negation, pronoun ambiguity, changed identity and unintended edits to unrelated nodes. Public model listings need authenticated discovery before routing; live YouArt access remains unverified.

## MotionSites

Source: https://motionsites.ai/ — landing-page prompt-library categories and animated-background offering read. This surface sells reusable prompts for pages/sections and directs users to another design library. The public page does not establish a general natural-language compiler, working application backends or deployed acceptance. Paid prompt text was not fetched or copied.

MGR implementation decision: independently author structured route/action/content/motion contracts from user requirements, then verify the actual built experience. A decorative hero does not satisfy a requested persistent form, authenticated dashboard or checkout. Current native output supports bounded responsive content pages, links and disclosures; arbitrary app/backend synthesis and browser acceptance remain open. Chrome/Edge headless launch failures in this environment provide no evidence of working browser interactions.

## Promotion rule

Public product descriptions supply leads and explicit observations, not proof of implementation equivalence. No new branch is promoted by this document. The 75 individual studies retain their unresolved original scope, and the Hollywood comparison protocol still requires actual matched outputs, failed-attempt costs and blinded craft review.

# BEAST University — Source Universe

BEAST University must not become “search GitHub and stop.”

For every research question, deliberately scan multiple source classes when relevant:

## Code/model ecosystems
- GitHub and GitLab: source, issues, releases, architecture, maintenance, tests.
- Hugging Face Hub: models, datasets, Spaces, papers, model cards, licenses, evals and demos.
- ModelScope and other reputable model hubs where relevant.
- npm, PyPI, crates.io and package registries for implementation ecosystems.

## Research/standards
- arXiv, Papers with Code and publisher/author pages.
- W3C, WHATWG, IETF/RFCs, ISO/public standards material, Khronos/OpenUSD/industry specs where applicable.
- Vendor engineering blogs and official technical documentation.

## World-class production systems
Study top systems outside AI too: film/VFX/animation pipelines, Universal/major studio production concepts where publicly documented, Pixar/OpenUSD, Adobe creative supply chain, game engines, broadcast, publishing, manufacturing, logistics, music production, design systems, analytics and workflow orchestration.

## Product/community evidence
Official docs first for capabilities. Then issue trackers, forums, Reddit/community discussions, benchmarks, case studies and independent reviews for failure modes and real-world experience. Community popularity is evidence of usage, not proof of correctness.

## Commercial systems
Study what leading commercial systems expose publicly: product behavior, docs, APIs, architecture talks, integrations, pricing/cost shape, enterprise controls and workflows. Do not scrape or copy private/proprietary paid material.

## BEAST source rule
Use the best source for each claim. Cross-check important claims. Record date, version, license, source URL, evidence strength, capability lesson, risk, and whether we should ADOPT, ADAPT, STUDY ONLY, or REJECT.

## Compatibility and next engineering

The objective service remains in-memory. Its request cache is not durable job/approval/expense custody. New processes must resolve existing downstream original identities, not assume that losing the cache permits retry. A rejected attempt requires reconciliation. BLOCKED project results are cached outcomes; a genuine production resume/checkpoint contract is still needed, not repeated new request keys or blanket automatic retries.

Factory request IDs now include the tenant/workspace/objective/workstream tuple; old `<objective>:<workstream>` concatenation is unsafe. Any external custom adapter with old in-flight jobs must explicitly migrate/reconcile their original IDs before using the new version. No automatically connected production objective adapter was found in this inspected bootstrap/native route; native document/Forge request IDs and saved permanent records were not rewritten. Default factories remain honestly blocked where real output adapters are missing. Research-only metadata success is not media output.

Next: durable original project/resume state through existing Creation repository contracts; trusted actor/right/approval context; genuine shared-edge adapter and returned-file criteria; owner experience and full user acceptance. Reuse ONE/API/domain job custody rather than introducing another ledger or delegating grants from a plan. Direct basic Forge remains independent of Creation. Actual two-output fixture demonstrates reuse feasibility, not deployment completion or measured monetary savings. Local compute, ongoing maintenance and quality comparison remain unmeasured.
